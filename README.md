# Ninja Status Bot

Автоматическая система мониторинга статусов производственных проектов через Telegram. Бот анализирует переписку в рабочих чатах, обновляет статусы по этапам проекта и отправляет сводки продюсерам и клиентам.

---

## Что изменилось (refactor-ветка)

Ключевые изменения относительно продакшн-версии:

- **Один бот вместо двух** — Silent Bot и Smart Bot объединены в один. Бот и собирает сообщения из чатов, и общается с продюсерами в личке.
- **Динамические пайплайны** — блоки берутся из дашборда OCTOPUS, ничего не захардкожено. Дашборд — единый источник правды.
- **Ручные статусы из дашборда** — имеют приоритет над AI (кроме "Не определён").
- **Два формата** (короткий/длинный) — визуально разные, переключаются кнопкой, с цветовыми маркерами.
- **Кнопочный интерфейс** — продюсеру не нужно помнить команды, всё через inline-кнопки.
- **Настройки из бота** — формат, отправка клиенту переключаются кнопками.
- **Клиентская доставка с одобрением** — статус сначала идёт продюсеру, он решает отправлять ли клиенту.
- **Ссылки на источники** — AI цитирует конкретные сообщения, в статусе появляются кликабельные ссылки в чат.
- **Глоссарий** — базовый + автообнаружение терминов + редактирование/одобрение/отклонение.
- **Синхронизация в дашборд** — AI-статусы пишутся обратно в OCTOPUS.

## Как это работает

### 1. Сбор сообщений

Бот добавляется в проектный чат Telegram. В группах он молча фиксирует каждое сообщение и сохраняет в таблицу `messages` с привязкой к `telegram_chat_id` и `telegram_message_id` (для ссылок).

При добавлении в чат отправляет приветственное сообщение с политикой обработки данных. Также отправляет продюсеру личное сообщение с информацией о проекте и кнопкой настроек.

Каждый чат привязан к проекту через таблицу `chats`. У проекта может быть несколько чатов. Для анализа берутся сообщения из всех чатов проекта.

### 2. Анализ статусов

Запускается двумя способами:
- **По расписанию**: `status-scheduler.ts` — каждый час проверяет, пора ли отправить (по настройкам дня/времени проекта)
- **Вручную**: команда `/analyze` или `/admin_analyze [ID]`

Процесс:
1. Загружает последние сообщения из всех чатов проекта
2. Определяет роль каждого отправителя (продюсер / клиент / команда)
3. Форматирует переписку с тегами: `[#123][Продюсер Иван]: текст`
4. Получает активные блоки из дашборда OCTOPUS
5. Отправляет в AI сервис (`/analyze/dynamic-blocks`)
6. AI анализирует каждый блок и генерирует статус с цитатами `[#123]`
7. Сохраняет результаты в `custom_block_statuses`
8. Синхронизирует статусы обратно в дашборд OCTOPUS

### 3. Приоритет статусов

```
1. Ручной статус из дашборда OCTOPUS (если != "Не определён")
2. AI-статус из custom_block_statuses
3. Нет информации (если ни того, ни другого)
```

### 4. Отправка статусов

По расписанию из `client_settings` бот:
1. Собирает все статусы (ручные + AI)
2. Форматирует в выбранном формате (короткий / длинный)
3. Заменяет теги `[#id]` на кликабельные ссылки в чат
4. Отправляет продюсеру в личку
5. Если включена отправка клиенту — показывает продюсеру кнопки:
   - **Отправить клиенту** — бот пересылает короткий формат клиенту
   - **Пропустить** — не отправлять
   - Кнопки живут 24 часа, потом автоудаляются

### 5. Уточняющие вопросы по статусу (реплай)

Продюсер может задать вопрос по конкретному проекту — для этого нужно **сделать реплай (ответить) на сообщение со статусом** и написать вопрос. Бот определит проект из статуса, отправит вопрос на AI-сервис (`/answer/question`) и вернёт ответ на основе переписки проекта.

> Просто написать боту текст без реплая не получится — бот не поймёт, к какому проекту относится вопрос. Контекст проекта сохраняется 10 минут после реплая, в течение которых можно задавать дополнительные вопросы.

## Два формата статусов

### Короткий формат

Компактный нумерованный список. Краткое описание на каждый блок. Согласованные блоки сгруппированы. Блоки без информации скрыты.

```
1. ❤️Монтаж
Ждем ОС от клиента 📎

2. 💛Кастинг
В работе, коллбек завтра 📎

3. 💚Согласовано
Музыка, ЦК, VFX
```

### Длинный формат

Полный текст по каждому блоку с буллетами. Группировка по фазам (пре/пост-продакшн) если есть обе фазы. Блок "Ждём от клиента" внизу.

```
🎬 Пре-продакшн:

1. 💛Кастинг
- Актёры найдены 📎
- Коллбек 5 марта 📎

2. 💚Локации
- Согласовано клиентом 📎

🎞️ Пост-продакшн:

1. ❤️Монтаж
- Отправили 24.12 📎
- Ждём ОС от клиента (перенесено на 12-13 января) 📎

2. 💚Музыка
- Согласовано клиентом 📎

‼️ Ждём от клиента:
- Монтаж: Ждем ОС от клиента
```

### Цветовая маркировка

| Маркер | Категория | Ключевые слова |
|--------|-----------|----------------|
| ❤️ | Важное, ждём решения | ждем ОС, нужно утвердить, на согласовании, требуется |
| 💛 | В работе | в работе, отправили, делаем, готовим |
| 💚 | Согласовано | согласовано, утверждено, одобрено, окнули |

Блоки без информации ("информация отсутствует") — скрыты в коротком формате, показываются списком в длинном.

### Ссылки на источники (📎)

AI при анализе цитирует конкретные сообщения из переписки. В статусе они отображаются как кликабельные 📎 — нажав, можно перейти прямо к сообщению в Telegram-чате.

Для работы ссылок:
- Колонка `telegram_message_id` в таблице `messages` (добавлена)
- Бот должен собирать сообщения из реальных чатов
- Старые сообщения без `telegram_message_id` — ссылки просто не покажутся

## Интерфейс бота

### Для продюсеров (кнопочный)

Продюсер пишет `/start` в личку боту. Появляются inline-кнопки:

```
/start
  |
  ├── [Статусы проектов]
  │     ├── [Rocketbank] --> статус в выбранном формате
  │     │                     ├── [Настройки]
  │     │                     └── [К проектам]
  │     └── [Другой проект] --> ...
  |
  └── [Настройки рассылки]
        ├── [Rocketbank] --> текущие настройки
        │                     ├── [Сменить формат] --> сразу показывает превью в новом формате
        │                     ├── [Клиенту: вкл/выкл]
        │                     ├── [Статус проекта]
        │                     └── [К проектам]
        └── [Другой проект] --> ...
```

### Текстовые команды

| Команда | Описание |
|---------|----------|
| `/start` | Приветствие + кнопки |
| `/status` | Статусы всех проектов |
| `/status Rocketbank` | Статус конкретного проекта (поиск по имени) |
| `/settings` | Настройки рассылки |
| `/settings Rocketbank формат короткий` | Изменить настройку текстом |
| `/analyze` | Запустить AI-анализ вручную |
| `/help` | Список всех команд |
| `/reset` | Сбросить контекст диалога |

### Настройки проекта

При нажатии на проект в "Настройки рассылки":

| Параметр | Описание | По умолчанию |
|----------|----------|--------------|
| Дни | Дни отправки (Mon,Tue,Wed,Thu,Fri) | Пн-Пт |
| Время | Время отправки | 10:00 МСК |
| Формат | Короткий / Длинный | Длинный |
| Тихие часы | Не отправлять в указанный период | Не настроены |
| Выходные | no / urgent / normal | Не настроены |
| Клиенту | Отправлять ли клиенту | Выключена |

Формат и отправка клиенту переключаются кнопками. При смене формата сразу показывается превью статуса в новом формате.

Настройки хранятся в таблице `client_settings` (Supabase). Если для проекта нет записи — используются значения по умолчанию.

## Глоссарий

Бот ведёт глоссарий терминов видеопродакшна, чтобы AI лучше понимал профессиональный сленг (ОС, ЦК, PPM, стайлшоты, прешут и т.д.).

**Базовый глоссарий** — предустановленные термины, всегда активны.

**Автообнаружение** — AI может находить новые термины из переписки проекта. Найденные термины попадают в pending. Их нужно одобрить, отклонить или отредактировать через админские команды.

**Хранение** — база: Python-файл, обнаруженные: JSON-файл в `ai-service/data/`.

## База данных

### Status Ninja DB (Supabase)

| Таблица | Описание |
|---------|----------|
| `projects` | Проекты (ID, имя, producer_id, client_id) |
| `chats` | Telegram чаты привязанные к проектам |
| `messages` | Собранные сообщения из чатов |
| `producers` | Продюсеры (имя, telegram_chat_id) |
| `clients` | Клиенты (имя, client_chat_id) |
| `client_settings` | Настройки по проектам (формат, расписание, тихие часы) |
| `custom_block_statuses` | AI-статусы по блокам (project_id + block_id) |
| `system` | Системные флаги |

### Ключевые поля messages

| Поле | Тип | Описание |
|------|-----|----------|
| `message_id` | int8 | Auto-ID (PK) |
| `telegram_chat_id` | text | ID чата в Telegram |
| `telegram_message_id` | int8 | ID сообщения в Telegram (для ссылок 📎) |
| `sender_id` | text | Telegram ID отправителя |
| `message_text` | text | Текст + извлечённые ссылки |
| `is_analyzed` | bool | Обработано ли AI |
| `timestamp` | timestamptz | Время сообщения |

### Dashboard DB (OCTOPUS)

Отдельный Supabase. Содержит:
- `custom_tasks_pre` / `custom_tasks_post` — кастомные блоки проекта (пре/пост-продакшн)
- Ручные статусы блоков (приоритет над AI)
- Бот читает активные блоки и ручные статусы оттуда, пишет AI-статусы обратно

## Как подключить новый проект

1. **Дашборд OCTOPUS** — создать проект, настроить блоки
2. **Supabase** — проект в `projects` с привязкой к producer и client; продюсер в `producers` с `producer_tg_chat_id`
3. **Telegram** — добавить бота в проектный чат
4. Бот начнёт собирать сообщения автоматически
5. Продюсер пишет `/start` боту в личку — видит свои проекты и кнопки

По умолчанию: статусы Пн-Пт в 10:00 МСК, длинный формат, клиенту выключено.

## Установка и запуск

### Backend (Node.js)

```bash
cd backend
npm install
cp .env.example .env    # заполнить переменные
npx ts-node src/index.ts
```

### AI сервис (Python)

```bash
cd ai-service
pip install -r requirements.txt
uvicorn src.api:app --reload --port 8000
```

### Порядок запуска

1. AI сервис (порт 8000)
2. Backend (порт 3000) — бот поднимается автоматически
