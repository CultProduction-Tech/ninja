# Обновленная архитектура Ninja Status Bot

## ✅ Правильная структура (как в n8n)

### Бот 1: Silent Bot (Молчаливый) 🤫
**Токен:** `TELEGRAM_BOT_TOKEN`

**Функции:**
- Добавляется в чаты проектов (клиент + команда)
- Отправляет приветственное сообщение при входе
- Молчит и только собирает сообщения
- Сохраняет все сообщения в Supabase

**Файлы:**
- `backend/src/bot/telegram.ts` - setup Silent Bot
- `backend/src/workflows/collect-messages.ts` - сбор сообщений

---

### Бот 2: Smart Bot (Умный) 🤖
**Токен:** `TELEGRAM_PRODUCER_BOT_TOKEN`

**Функции - ВСЁ В ОДНОМ БОТЕ:**

1. **Анализ по таймеру ⏰**
   - Каждые 8 часов (настраивается)
   - Анализирует новые сообщения через AI
   - Проставляет статусы в БД
   - Отправляет уведомления продюсерам

2. **Чат с продюсерами и клиентами 💬**
   - Различает продюсеров и клиентов (по БД)
   - Разные стили общения для разных типов пользователей
   - Память диалога (помнит контекст)
   - Ищет проекты и отвечает на вопросы

3. **Команды:**
   - `/start` - приветствие (разное для продюсеров/клиентов)
   - `/analyze` - запустить анализ вручную (только продюсеры)
   - `/status` - показать статусы проектов

**Файлы:**
- `backend/src/bot/smart-bot.ts` - весь функционал
- `backend/src/workflows/trigger.ts` - scheduler
- `backend/src/workflows/orchestrator.ts` - анализ
- `ai-service/src/api.py` - endpoint `/chat/context`
- `ai-service/src/chains/analyzer.py` - AI логика
- `ai-service/src/prompts/templates.py` - промпты

## Workflow: Как работает анализ

```
⏰ Каждые 8 часов (или ручная команда /analyze)
    ↓
🔍 Проверка новых сообщений в чатах
    ↓
📊 Для каждого чата:
    - Получить непроанализированные сообщения
    - Получить проект
    - Отправить в AI сервис
    ↓
🤖 AI анализирует 43 поля проекта
    ↓
💾 Сохранение статусов в БД
    ↓
✉️ Отправка уведомлений продюсерам через Smart Bot
    ↓
✅ Готово
```

## Различия в общении

### Продюсеры
**Стиль:** Деловой, профессиональный, прямолинейный

**Возможности:**
- Вопросы о любых проектах
- Команда `/analyze` для ручного запуска
- Детальная информация о статусах
- Доступ ко всем проектам

**Пример:**
```
Продюсер: Какой статус монтажа в проекте X?
Бот: Монтаж проекта X: клиент ожидает правки до 15 марта.
     Cult версия готова, отправлена 12 марта.
```

### Клиенты
**Стиль:** Вежливый, заботливый, клиентоориентированный

**Возможности:**
- Вопросы только о своих проектах
- Упрощенные объяснения
- Нет доступа к команде `/analyze`

**Пример:**
```
Клиент: Когда будет готов монтаж?
Бот: Здравствуйте! Монтаж вашего проекта будет готов
     к 15 марта. Мы пришлем вам версию на согласование.
```

## API Endpoints

### Backend (порт 3000)
- `GET /health` - проверка
- `POST /webhook/update_start` - запустить анализ

### AI Service (порт 8000)
- `GET /health` - проверка
- `POST /analyze/status` - анализ всех 43 полей
- `POST /chat/context` - **НОВЫЙ!** Чат с контекстом пользователя
- `POST /chat` - простой чат (legacy)

## Что изменилось

### ❌ Было (неправильно):
- Producer Agent - отдельный бот только для чата
- Scheduler - только анализ, без чата
- Нет различия продюсеров/клиентов

### ✅ Стало (правильно):
- **Smart Bot = анализ + чат + уведомления**
- Различает продюсеров и клиентов
- Разные промпты для разных типов
- Ищет проекты и отвечает с контекстом

   - Команда `/analyze` - должен запустить анализ
